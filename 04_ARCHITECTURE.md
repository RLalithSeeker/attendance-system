# Architecture and trust boundaries

Webcam/consented source → existing CamBrain detector → REAL face identity matcher + enrolled template gallery (on-prem) → narrow AttendanceRecognitionAdapter → teacher-approved class session/check-in service → cloud-ready FastAPI endpoints → attendance database → teacher dashboard/CSV.

Separate concerns: face detection = boxes; face identity recognition = calibrated matching to an enrolled identity; tracking ID/Re-ID = temporal track, NOT verified student identity; VLM narration = NOT identity. Recognition decision must depend on enrolled face templates and defined threshold/ambiguity policy, never class roster alone. Only enrolled students assigned to active class qualify.

Default inference and templates local on school-owned machine; optional cloud host contains identity metadata and attendance records, not raw footage or biometric vectors. Encryption in transit, server auth, least privilege. Document that local inference + hosted API/database/dashboard qualifies as hybrid cloud deployment only when actually configured and deployed. No camera upload to external provider. Threats: impersonation via photos, false positives, wrong-roster attendance, duplicate concurrent frames, leaked biometrics, overly broad teacher access, unsafe exports, replayed event requests, unconsented processing. Mitigate via supervised capture and teacher approval; mark robust liveness as out of scope unless independently validated.

Module suggestions subject to audit: `attendance/{models,schemas,repository,service,recognition_adapter,routers,auth}` or equivalent under actual backend. Register routers with existing app; reuse existing frontend component system and ORM. Integration adapter exposes `enroll(student_id, consent_context, frames)->template_ref`, `identify(frame)->RecognitionResult(identity|unknown|ambiguous, score?, model_version, reason)`; do not expose embedding in API responses. Mock adapter injectable only in tests and `DEMO_MODE=true` clearly indicated, never production.

For multiple faces, prefer reject frame and instruct one-person-at-a-time in MVP rather than incorrectly assigning all faces. For one student, require stable repeated matches across a configurable short window as defense against transient error, but do not treat it as spoof proof. Teacher-controlled session gate and human-review queue. Store time UTC, display user-selected course timezone.
