# Definition of done and release gate

Mark each item PASS / FAIL / BLOCKED with test evidence. Core: [ ] existing CamBrain features preserved [ ] working local startup [ ] teacher auth [ ] student/roster CRUD [ ] recorded consent [ ] enrolled face identity matching validated or honestly disabled [ ] unknown/ambiguous rejected [ ] active session gating [ ] duplicate-free atomic attendance [ ] manual review/correction with reason/audit [ ] CSV export [ ] UI all flows [ ] SQLite migration [ ] Postgres configuration prepared [ ] biometric revocation/deletion [ ] protected routes [ ] actual automated tests passing [ ] camera real E2E when possible [ ] cloud deployment status accurately stated.

Ship `docs/attendance/HANDOFF.md`: branch/commit/status; changed paths; commands copied from actual repo; architecture diagram; actual features and screenshots if produced; model/weights/license; real vs simulated recognition; exact environmental dependencies, active blockers, results; security limitations and photo spoofing disclaimer; demo runbook; next five prioritized fixes. Include `docs/attendance/TEST_RESULTS.md`, `REPO_AUDIT.md`, `.env.example`, migrations and scripts if needed. Do not assert '100% complete', 'cloud deployed', or 'liveness protected' without proof.

Demo sequence: sign in → create course → add fictional test roster → enroll consented volunteer locally → start class → successful match (if real model available) → duplicate ignored → unknown refused → manual exception → close session → download CSV → show audit → explain cloud architecture/status and privacy. If no real matcher, show manual workflow and explicitly label simulated adapter demo.
